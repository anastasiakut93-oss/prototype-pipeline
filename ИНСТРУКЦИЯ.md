# Как собрать кликабельный прототип

Инструкция для тех, кто не пишет код. Знать HTML не нужно, открывать терминал —
почти не нужно. Первый прототип занимает от получаса до вечера, в зависимости от
того, сколько экранов.

## Что понадобится

- Claude Code — приложение на компьютере или расширение в редакторе;
- полчаса времени и понимание, для кого прототип.

Всё. Ничего устанавливать вручную, ничего настраивать не надо.

## Шаг 1. Установка, один раз

Откройте Claude Code и введите две команды — по очереди, дождавшись первой:

```
/plugin marketplace add anastasiakut93-oss/prototype-pipeline
```

```
/plugin install clickable-prototype@prototype-pipeline
```

Оттуда же ставится всё, что пайплайн использует по ходу. Минимальный набор —
четыре штуки:

```
/plugin install ui-ux-pro-max@prototype-pipeline
/plugin install ux-strategy@prototype-pipeline
/plugin install visual-critique@prototype-pipeline
/plugin install designer-toolkit@prototype-pipeline
```

Полный список — в [README](README.md). Без них прототип тоже соберётся, просто
получится проще: оформление будет подобрано на глаз, а не по базе стилей.

Проверить, что встало:

```
/plugin list
```

## Шаг 2. Новая папка под проект

Каждый прототип живёт в своей папке. Проще всего создать пустую папку в
Финдере — например, `Документы/прототипы/доставка` — и открыть её в Claude Code
через «Открыть папку».

Это важно: если запускать в папке с другим проектом, файлы перемешаются.

## Шаг 3. Запуск

Напишите:

```
/prototype панель оператора доставки: приём заявок, склад, отчёты
```

Одной фразы достаточно — дальше вас будут спрашивать. Если материалы уже есть,
скажите об этом сразу:

```
/prototype ~/Документы/исследование-доставка — собери прототип по этим материалам
```

Подойдёт что угодно: транскрипт встречи, документ с болями, выгрузка из Excel,
презентация. Чем больше настоящего на входе, тем меньше вопросов и тем точнее
результат.

## Шаг 4. Ответы на вопросы

Вопросов будет не больше семи, по одному за раз. Спросят про роли, про то, что
эти люди делают каждый день, что у них сейчас болит, какие сущности крутятся в
работе и кому вы это показываете.

Три вещи, которые сильно улучшают результат:

**Отвечайте про боль конкретно.** Не «неудобно работать», а «чтобы ответить
клиенту про сроки, оператор обзванивает четыре склада и тратит час». Из первого
получится безликая таблица, из второго — экран, в котором заказчик узнает себя.

**Дайте настоящие данные, если они есть.** Выгрузка, скриншот таблицы, список
филиалов с сайта. Прототип на реальных числах убеждает в разы лучше выдуманного.

**Не знаете — так и скажите.** Вам предложат вариант, вы кивнёте. Это быстрее,
чем идти уточнять.

Про технологии вас спрашивать не будут — это не ваша забота. Единственный вопрос
про внешний вид: есть ли брендовые цвета и шрифты.

## Шаг 5. Согласование по ходу

Работа идёт этапами, и на четырёх из них всё останавливается и ждёт вас:

| Что показывают | Что смотреть |
|---|---|
| Карту экранов | Все ли разделы нужны, ничего ли не забыто |
| Примеры данных | Похоже это на реальность вашего клиента или нет |
| Каркас | Меню, шапка, переключение ролей — то ли это вообще |
| Каждый экран | По одному, со скриншотом |

**Не молчите на этих остановках.** Правка карты экранов стоит две минуты, правка
готовых экранов — час. Если на карте написано «Перемещения», а у клиента это
называется «переброски» — скажите сразу.

Отвечать можно как угодно: «ок», «убери отчёты», «поменяй местами первые два»,
«клиент называет это иначе».

## Шаг 6. Результат

В папке появятся два файла:

- `index.html` — сам прототип. Откройте двойным кликом, он запустится в браузере.
- `README.md` — описание: какие роли, где переключатель, что работает.

Файл самодостаточный. Его можно переслать в мессенджере, открыть на чужом
ноутбуке, показать без интернета. Никаких установок на той стороне не нужно.

Если нужна ссылка, а не файл, — попросите: «выложи на GitHub Pages» или
«опубликуй ссылкой». Ссылка по умолчанию приватная.

## Что важно знать про прототип

Это макет для демонстрации, а не работающая система:

- введённое **пропадает при обновлении страницы** — данные живут только в памяти
  браузера;
- никакой авторизации, сервера и настоящего сохранения нет;
- роли переключаются вручную, права доступа не работают по-настоящему.

Скажите об этом заказчику в начале встречи одной фразой — иначе первый же
нажатый F5 вызовет неловкую паузу.

## Частые ситуации

**«Собрал не то»** — скажите, что не так, своими словами. Переделать один экран
быстро. Если промахнулись концептуально — попросите вернуться к карте экранов.

**«Хочу другой цвет»** — «сделай акцент зелёным», «возьми цвета с сайта клиента
такого-то». Оформление меняется в одном месте, перекрашивается весь прототип
целиком.

**«Заказчик просит сохранять данные по-настоящему»** — это уже разработка, а не
прототип. Прототип для другого: проверить, правильно ли понята задача, и
договориться до того, как что-то начнут писать всерьёз.

**«Прототип разросся и стал медленным»** — значит, экранов слишком много для
одной встречи. Спросите, какой сценарий показываете, и соберите второй прототип
только под него.

**«Нужно на телефоне»** — скажите об этом на старте: «это мобильное приложение».
Оболочка соберётся в виде телефона с нижним меню, а не как система с боковым.

**«Пропала команда `/prototype`»** — проверьте `/plugin list`. Если плагина нет,
повторите шаг 1.

## Что дальше

Прототип можно передать разработчикам — попросите «собери спецификацию для
разработки». Можно подготовить к защите — «объясни, почему принял такие решения».
Можно собрать презентацию по нему.

Всё это делается той же фразой в чате, отдельных команд знать не нужно.
