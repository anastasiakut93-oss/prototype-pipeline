# Оформление: откуда берутся стили

Прототип не должен выглядеть как чужой шаблон. При этом подбирать палитру и шрифты
на глаз — долго и ненадёжно. Поэтому оформление берётся из базы `ui-ux-pro-max`:
там подобранные под тип продукта стили, палитры, шрифтовые пары и, что важнее
всего, списки антипаттернов — чего в этом типе интерфейса делать не надо.

## Шаг 1. Один вопрос человеку

Перед подбором спроси ровно одно:

> «Есть брендовые цвета и шрифты, которых надо держаться, или подобрать самому?»

Если бренд есть — попроси hex-коды или ссылку на сайт, откуда их взять. Если нет —
подбираешь сам и показываешь результат словами, а не палитрой в вакууме:
«спокойный сине-серый интерфейс, оранжевый только на действиях — подойдёт?»

Больше вопросов про оформление не задавай. «Какой стиль вам нравится?» человек без
опыта в дизайне интерфейсов отвечает наугад, и ответ всё равно приходится
переделывать, когда он увидит экран.

## Шаг 2. Подбор через ui-ux-pro-max

Найди скрипт — он лежит либо в личных скиллах, либо в кеше плагинов:

```bash
SEARCH=$(find ~/.claude/skills ~/.claude/plugins/cache -maxdepth 6 \
  -path "*ui-ux-pro-max*" -name search.py 2>/dev/null | head -1)
```

Запусти подбор дизайн-системы, описав продукт своими словами — тип, отрасль,
настроение:

```bash
python3 "$SEARCH" "internal CRM logistics operations dense tables" --design-system -p "Название проекта"
```

Запрос — на английском, это язык базы. Три-пять слов работают лучше длинной фразы.

Ответ приходит структурой: паттерн страницы, стиль, палитра из пяти цветов,
шрифтовая пара с ссылкой на Google Fonts, ключевые эффекты, антипаттерны и
чек-лист перед сдачей. Например, для внутренней CRM: стиль `Data-Dense Dashboard`,
основной `#2563EB`, действие `#F97316`, шрифт Inter, и предупреждение избегать
нарядного оформления и экранов без фильтрации.

Если проект многоэкранный и работа затянется на несколько сессий, добавь
`--persist` — рядом появится `design-system/MASTER.md`, к которому можно
возвращаться:

```bash
python3 "$SEARCH" "<запрос>" --design-system --persist -p "Название проекта"
```

Дополнительные выборки, когда нужного не хватило:

```bash
python3 "$SEARCH" "fintech trust"  --domain color
python3 "$SEARCH" "elegant editorial" --domain typography
python3 "$SEARCH" "real-time dashboard" --domain chart
python3 "$SEARCH" "onboarding" --domain ux
```

## Шаг 3. Перенос в токены прототипа

Подобранное раскладывается в переменные `:root` из `html-skeleton.md`. Соответствие
прямое:

| Что вернул подбор | Куда кладётся |
|---|---|
| Primary | `--accent`, плюс затемнённый вариант в `--accent-dark` и светлый фон в `--accent-bg` |
| CTA / акцент действия | `--warning` либо отдельная `--cta`, если действие важнее предупреждений |
| Background | `--bg` |
| Text | `--text`, приглушённые варианты в `--text-muted` и `--text-faint` |
| Шрифтовая пара | `--font-head` и `--font-body` |
| Эффекты | радиусы `--radius*`, тени `--shadow*`, длительность `--dur` |

Служебные цвета — успех, ошибка, предупреждение — берутся не из подбора, а
остаются стандартными: зелёный, красный, оранжевый. Это единственное место в
интерфейсе, где оригинальность вредна: пользователь читает эти цвета не глядя.

Затемнить или осветлить цвет для парных переменных проще всего через готовые
шкалы вроде Tailwind (`blue-600` → `blue-700` → `blue-50`), а не подбирая руками.

## Шаг 4. Шрифты

По умолчанию — системный набор из каркаса. Он ничего не грузит, выглядит опрятно
и работает без интернета. Для внутренних инструментов этого достаточно.

Подключать Google Fonts стоит, когда прототип показывают публично и внешний вид
важен сам по себе: лендинг, приложение для клиентов, презентация концепции.
Тогда — один `@import` в начале `<style>` и обязательно системный запасной
вариант в самой переменной:

```css
@import url('https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&display=swap');
:root{
  --font-body: Inter, ui-sans-serif, -apple-system, "Segoe UI", Roboto, Arial, sans-serif;
}
```

Запасной вариант здесь не формальность: прототип часто открывают на встрече без
интернета или с закрытым доступом к внешним доменам, и без него текст поедет.

Больше двух шрифтов в прототипе не нужно. Если подбор предложил пару с одинаковым
названием для заголовков и текста — это нормально, разница делается насыщенностью
и размером.

## Шаг 5. Проверка перед сдачей

`ui-ux-pro-max` вместе с подбором возвращает чек-лист. Пройди его по прототипу:

- контраст текста не ниже 4.5:1;
- фокус виден при переходе табуляцией;
- иконки — SVG, а не эмодзи;
- `cursor: pointer` на всём нажимаемом;
- переходы 150–300 мс, `prefers-reduced-motion` учтён;
- ширины 375, 768, 1024, 1440 не ломают вёрстку — в том объёме, в каком прототип
  вообще должен быть адаптивным.

Отдельно посмотри список антипаттернов для выбранного стиля. Это самая полезная
часть выдачи: она ловит не «некрасиво», а «в таком интерфейсе так не делают».

## Если ui-ux-pro-max недоступен

Пайплайн на этом не останавливается. Подбери оформление через `ui-design:color-system`
и `ui-design:typography-scale`, а если и их нет — возьми нейтральные токены из
`html-skeleton.md` и подкрути акцентный цвет под бренд клиента. Нейтральный,
аккуратный интерфейс лучше яркого и случайного.

Прогон через `design-taste-frontend` полезен в любом случае: он ловит именно
шаблонность — одинаковые карточки с иконкой и заголовком, градиент через весь
экран, три колонки преимуществ.
