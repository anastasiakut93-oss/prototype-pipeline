# Этап 3. Данные

Данные — то, из-за чего прототип либо убеждает, либо выглядит как студенческая
работа. «Иван Иванов, Товар 1, 100 ₽» сообщает заказчику, что задачу не поняли.
«Точка Академическая, Minako Monster, свободных 0» — что поняли.

## Три источника, по убыванию ценности

**1. Реальная выгрузка клиента.** Excel, отчёт, скриншот таблицы, список с сайта.
Возьми оттуда пропорции и названия. Не обязательно копировать все строки —
достаточно, чтобы соотношения были настоящими.

**2. Публичные данные клиента.** Список филиалов с сайта, каталог моделей,
прайс. Часто закрывает половину справочников.

**3. Генерация.** Когда взять неоткуда — генерируй, но по правилам ниже.

Всегда оставляй в коде комментарий с источником:

```js
// Пропорции по реальным остаткам точки Академическая
// (источник: Сводная_таблица_электровелосипеды.xlsx).
// Свободных велосипедов почти нет ни по одной модели — это и есть Боль 1.
```

Через две недели никто, включая тебя, не вспомнит, откуда взялись цифры, а на
встрече заказчик обязательно спросит.

## Генерация должна быть детерминированной

`Math.random()` в прототипе недопустим: человек обновит страницу во время
демонстрации, и все числа поменяются. Заказчик это заметит.

Синус от индексов даёт стабильный псевдослучайный результат без библиотек:

```js
function seeded(a, b, c) {
  const x = Math.sin(a * 17.31 + b * 7.13 + c * 5.19 + 1) * 10000;
  return x - Math.floor(x);           // стабильное число в [0, 1)
}

// Возведение в квадрат смещает распределение к нулю —
// так дефицитных позиций получается много, а изобильных мало.
const free = Math.floor(seeded(pointIdx, modelIdx, 0) ** 2 * 11);
```

Форма распределения важнее самих чисел. Если в жизни свободных велосипедов почти
нет — пусть и в прототипе почти везде будет ноль или единица, а не ровные
пятнадцать.

## Данные должны показывать боль

Это главный принцип этапа. Найди в интервью главную боль и сделай так, чтобы она
была видна на первом же экране без объяснений:

| Боль | Как выглядит в данных |
|---|---|
| Нечего выдавать клиентам | Столбец «свободно» почти весь в нулях и подсвечен красным |
| Заявки теряются | В очереди висят заявки трёхдневной давности |
| Никто не знает, где вещь | Половина позиций в статусе «в пути» без даты |
| Ручной пересчёт | Итоги в разных разделах не сходятся между собой |

Заказчик смотрит на экран и узнаёт свой вторник. Дальше разговор идёт про решение,
а не про то, правильно ли вы поняли задачу.

## Объём

- Списки: 15–40 строк. Меньше — не видно, как ведёт себя таблица; больше — файл
  разбухает, а пользы ноль.
- Справочники: 5–10 позиций.
- Карточки с историей: 3–5 записей, чтобы было видно и хронологию, и что она
  конечна.

## Названия

- Имена людей — обычные русские, разной длины. Обязательно возьми одно длинное
  («Константинопольская Е. В.») — оно проверит вёрстку таблицы.
- Даты — вокруг сегодняшнего дня, зафиксированного константой:
  `const TODAY = new Date('2026-07-16')`. Иначе прототип, открытый через месяц,
  покажет всё просроченным.
- Деньги — форматируй через `toLocaleString('ru-RU')`, иначе получишь `62000`
  вместо `62 000`.
- Идентификаторы — в формате клиента: если у него номера вида `АК-2026-0417`,
  используй их, а не `#1`.

## Состояние

Прототип живёт в памяти страницы. Данные лежат в обычных переменных, действия их
меняют, экран перерисовывается. Обновление страницы всё сбрасывает — это нормально
и объяснять человеку не нужно, если он сам не спросит.

`localStorage` подключай только если человек прямо просит, чтобы введённое
переживало перезагрузку. Чаще это только мешает: на демонстрации хочется вернуть
всё в исходное состояние одним F5.
